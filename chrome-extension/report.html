Why this design

Buyers need a quick way to compare homes, but listing copy and advertised prices are not the same as independent property context. The panel prioritizes a dated estimate with its range and confidence, then adds a short set of physical attributes. It stays beside the listing so the buyer can compare without switching tabs. These facts were chosen because value context helps assess the asking guide, while bedrooms, bathrooms, parking, type, and land area help compare the physical homes. Each is shown only when the API returns it.

The extension reads only an address from known address-specific fields, or accepts one typed by the user. It requests Microburbs facts only after matching that address. It does not collect or copy listing text or photos.

Coverage and data availability depend on the hackathon API. Estimates are automated and indicative; buyers should verify property details and seek professional advice before making a decision.

Live API spot-check

On 7 November 2026, six addresses shown in Domain's Waterloo sale-search results were checked against the live Microburbs address geocoder. Five returned an exact normalized address match; one returned no exact match among the API candidates. The extension now fails closed for that case and does not load facts for an unrelated candidate.

For the five matched homes, the API returned an automated valuation for two; three had bedroom, bathroom, and parking counts available. Other values were missing on some homes. This illustrates why estimates and property basics are shown only when returned, and why address confirmation and coverage limitations matter.

This was an API spot-check, not a claim that the unpacked extension was installed and end-to-end tested on all six listing pages. The demo video must show the extension running on real listings.
